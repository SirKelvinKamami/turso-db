# 2026-09-10 — v1.7.0: libsql replica sync (bidirectional LWW)

## Summary
Implemented the replica-sync plan as v1.7.0: databases can now run as `turso::sync`
replicas of a remote libsql hub (opt-in via `SYNC_ENABLED`, hub
`SYNC_HUB_URL`/`SYNC_HUB_TOKEN`, poll `SYNC_POLL_MS`). A single supervisor task
pulls/pushes/checkpoints each replica so replicas converge bidirectionally (LWW).
Unreachable hub ⇒ degrade to local-only with a warning.

## Key engineering lesson (see also lessons file)
- `turso::sync::Database` is `Send` but NOT `Sync`; `connect()` is NOT `Send` (its body
  uses `&self` after an internal await via the `extra_io` driver callback).
- Non-`Send` async work must run on a blocking thread inside a fresh current-thread
  runtime (`spawn_blocking` + `Runtime::block_on`) to keep axum handler futures `Send`.
- A `Result<T, Box<dyn Error>>` temporary in an `if let` binds across the whole
  statement — if the body awaits, the non-`Send` error arm lives across the await.
  Match on the `Result` and early-return instead.
- Guard regressions with `const fn _assert_send<T: Send>() {}` + calls in a `const _`.
